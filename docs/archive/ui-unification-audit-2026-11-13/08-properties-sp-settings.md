# 08 — Properties, Supplier Partner, Settings: UI unification audit

Read-only audit. Paths are relative to `client/src/` unless they start with `docs/`. "unverified" = not opened line by line (classified from grep counts only).

Depth note: the rental pages, all SP pages, `Settings.tsx`, the settings hubs, `MySettings`, `POSSettings` and the `FactorySettingsView` header were read in code. The ~60 leaf settings components (WhatsApp sections, data tools cards, user drawer, dialogs) were classified by targeted grep (headings, tabs, tables, confirm, loading, selects, dates, save labels) and are marked "grep" in the inventory.

## Inconsistency findings

### Properties / rentals

1. **One rental component, three page headers.** `PropertyRentalPage.tsx` renders a custom CSS hero with its own `<h1>` for Properties (`:430-446`), `PageHeader` with icon and children for ERP (`:448-455`), and an icon + `PageHeader` wrapped in a hand-built flex row for Factory (`:457-470`). `RentalPaymentsLog.tsx` repeats the split: full premium component for Properties (`:200-250`), `PageHeader` + toolbar for ERP (`:259-272`), flex-row variant for Factory (`:274-290`). The comment at `PropertyRentalPage.tsx:312` says "Factory keeps its hub strip". Standard: `PageHeader` (or `ErpPage`) with `icon` + actions for all three modules; keep module colour as a token only. Size M, risk low-medium (three CSS skins: `propertiesRentalsPremium.css` 353 lines, `propertiesPaymentsPremium.css` 452 lines, `factory-rental-shops.css`).

2. **Rental navigation model differs per company type.** Properties: one hub with URL-backed tabs Warehouses / Shops / Payments (`PropertiesRentalsHub.tsx:20-58`). Factory: three separate routes (`components/FactoryRoutes.tsx:388-390`). ERP: three separate routes (`routes/ErpRoutes.tsx:454-456`). Standard: the hub + tabs pattern for all three (the hub is ~70 lines and already generic apart from the wrapped pages). Size M, risk low (keep old URLs as redirects, as Properties already does).

3. **Payments Log is a different product per module.** Properties gets period/unit/tenant filters, copy-to-clipboard and a row menu (`PropertiesPaymentsPremium.tsx:198-261`, `:360`); Factory/ERP get search only, three hand-built stat cards and an icon delete button (`RentalPaymentsLog.tsx:300-330`, `:420-428`). Neither has Excel/PDF export or print; Properties' only "export" is clipboard TSV (`RentalPaymentsLog.tsx:139`, `:162`). Standard: one payments table with `SearchField` + `PeriodFilter` + `ErpReportExportMenu` for all modules; module policy only toggles reconciliation extras. Size L, risk medium (reconciliation maths is interleaved).

4. **"Payments Log" button missing on warehouse pages.** `paymentsLogUrl` is passed for Shops (`FactoryRentalShops.tsx:13`, `pages/erp/ErpRentalShops.tsx:12`) but not for Warehouses (`FactoryRentalWarehouses.tsx:6-12`; ERP warehouses likewise has no match), so the same screen shows the button on one unit type and not the other. In Properties the URL is passed but suppressed (`PropertyRentalPage.tsx:218-221`) because the tab exists. Standard: always pass it. Size S, risk low.

5. **Shops tab shows warehouse wording and icon.** Hero `aria-label="Warehouse rentals overview"` and subtitle "Manage warehouse units, payments, rents, guarantees, and contracts in one place." are unconditional (`PropertyRentalPage.tsx:431`, `:442`); the hero icon is always `Building2` (`:434`) and the `pageIcon` prop from the wrappers is ignored in Properties mode; both hub triggers use `Building2` (`PropertiesRentalsHub.tsx:42`, `:46`) while the wrappers import `Store` for shops. Size S, risk none.

6. **Raw tables and text-only states across all rental screens.** Raw `<table>`: `PropertyRentalPage.tsx:731`, `RentalPaymentsLog.tsx:349`, `PropertiesPaymentsPremium.tsx:282`, `LedgerView.tsx:313/428/469/515`, `BulkPaymentDialog.tsx:200`. Loading is text ("Loading units…" `PropertyRentalPage.tsx:688`, `:723`; "Loading payments…" `RentalPaymentsLog.tsx:341`, `PropertiesPaymentsPremium.tsx:274`). Empty states are bare `div`s (`PropertyRentalPage.tsx:690-694`). No search or filter on the unit list at all. Standard: `Table`/`ErpListTable`, `LoadingState`/`EmptyState` from `ui/page-state`, `SearchField`. Size M, risk low.

7. **Hand-rolled confirm dialogs.** Delete-unit and rename-group use raw `Dialog` + footer buttons (`PropertyRentalPage.tsx:1124-1170`, `:1177-1206`); payment delete has its own `RentalPaymentDeleteDialog.tsx`. Standard: the one shared confirm component the wider audit settles on. Size S, risk low.

8. **KPI tiles and colours.** Six hand-built `Card` tiles (`PropertyRentalPage.tsx:548+`) and three more in `RentalPaymentsLog.tsx:300-330` instead of `StatCard`/`KPICard`; `PropertiesDashboard.tsx:282-298` does use `KPICard`. Palette classes are hard-coded and the meaning of red/green flips by module (`PropertyRentalPage.tsx:514-531`: "TO COLLECT" green in Properties, "OUTSTANDING" red elsewhere). Standard: `StatCard` with a `tone` prop. Size S-M, risk low.

9. **Native form controls inside rental dialogs.** Native `<select>`: `PaymentForm.tsx:127`, `StartContractForm.tsx:131`, `UnifiedRentalAccounting.tsx:217`, `:468`. Native date inputs: `BulkPaymentDialog.tsx:168`, `EditInfoForm.tsx:144`, `EndContractForm.tsx:106`, `GuaranteeForm.tsx:241/300/399`, `PaymentForm.tsx:119`, `StartContractForm.tsx:117`, `UnifiedRentalAccounting.tsx:234`. Meanwhile `PropertiesPaymentsPremium.tsx:208-238` uses shadcn `Select`. Standard: shadcn `Select` + `date-picker-input`. Size M, risk low.

10. **Role checks bypass the Properties capability registry.** `PropertyRentalPage.tsx:214-221` and `:483` compare role strings directly (`currentRole === "Admin" || … "Developer"`), although phase 5 introduced `canUsePropertiesCapability` for exactly this. Size S, risk low.
