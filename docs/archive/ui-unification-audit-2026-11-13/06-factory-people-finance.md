## Inconsistency findings

1. **Employees vs Workers are two parallel implementations of the same module.** Same six jobs, different UI and capability.
   - Roster: `factoryworkers/FactoryWorkersRosterPanel.tsx` L188-292 (search + status + Filter panel + Actions▾ Template/Import/Export + "Add Worker", 11 columns) vs `FactoryEmployees.tsx` L340-373 (search + status + "New Employee", 5 columns, no import/export).
   - Payroll: `factorypayrolltab/components/PayrollOverview.tsx` L156-292 (batches, bulk pay, undo, Excel/PDF) vs `FactoryEmployeePayrollTab.tsx` L226-300 (department accordion + Run Payroll only).
   - Attendance: `FactoryAttendance.tsx` L414-525 (WhatsApp, print, Excel, range export, EN/AR) vs `FactoryEmployeeAttendanceTab.tsx` L274-372 (none of those; adds free-text Shift that the worker screen explicitly removed, `FactoryAttendance.tsx` L77).
   - Advances: `factoryadvancestab/advances/AdvancesPanel.tsx` L199-232 (5 toolbar actions, sub-tabs Repayments/Deductions) vs `FactoryEmployeeAdvancesTab.tsx` (single table).
   - Bonuses: `FactoryWorkerBonusesTab.tsx` L451,504 (Mark Paid / Delete, no export) vs `FactoryEmployeeBonusesTab.tsx` L305,586 (Reverse, CSV export, search + date range).
   - Detail: `factoryworkerdetail/FactoryWorkerDetailView.tsx` L335-366 (5 tabs) vs `FactoryEmployeeDetail.tsx` (no tabs, one table).
   - Standard: one parameterised "staff" module (`kind: "worker" | "employee"`) sharing roster table, attendance grid, advances, bonuses and detail layout; differences become config (columns/actions). Size **L**, risk medium-high (different APIs `/api/factory/workers` vs `/api/factory/employees`, payroll logic differs).

2. **Export/print is implemented seven different ways and labelled inconsistently; none uses `ErpReportExportMenu`.**
   - Manual CSV + `downloadBlob`: `FactoryCustomers.tsx` L261-285 ("Export").
   - Manual CSV + hand-made anchor, no BOM: `FactoryEmployeeBonusesTab.tsx` L161-164 ("Export").
   - Client xlsx via `excelHelper`: `daybook/factoryDaybookExports.ts` L49-50,138-139 ("Export ▾ Summary/Detailed"); `factoryattendance/utils.tsx` L443,528; `factoryworkers/useFactoryWorkersModel.tsx` L729 ("Export Salaries").
   - Server GET via `window.open`: `factorycustomerstatement/CustomerStatementExports.tsx` L33-49 ("Export PDF"/"Export Excel"); `factory-suppliers/LinkedSupplierExposure.tsx` L58-64.
   - Server POST → blob → anchor: `FactorySupplierReport.tsx` L64-84; `factorypayrolltab/components/PayrollRunDialogs.tsx` L489-509.
   - Server POST → blob → `window.open`: `factorypayrolltab/useFactoryPayroll.tsx` L472-481.
   - `window.print()` / generated HTML print window: `FactoryWorkerAttendanceReport.tsx` L351; `FactoryAttendance.tsx` L264-289.
   - Labels for the same thing: "Export" / "Export Excel" / "Excel" (`FactoryAttendance.tsx` L514) / "Export Salaries"; "Export PDF" that really prints (`factoryattendance/components/AttendanceActionsMenu.tsx` L69-72, Printer icon). Icons: `Download`, `FileDown`, `FileSpreadsheet`, `Printer`.
   - File names: `factory-customers.csv`, `Employee_Bonuses.csv`, `FactoryDaybook_<date>.xlsx`, `workers-salaries-<date>.xlsx`, `attendance-range-…xlsx`, `supplier-report-…`, `Payroll_…xlsx` (kebab vs Pascal vs snake; some dated, some not).
   - Standard: `ErpReportExportMenu` (one "Export ▾" with Excel / PDF / Print items) in the page/toolbar actions slot, `excelHelper` or server endpoint behind it, file name `factory-<entity>-<yyyy-mm-dd>.<ext>`. Size **M**, risk low (UI-only wrapper around existing handlers).
