# 07 — POS shell and RETAIL company type: UI unification audit

Scope: `client/src/pages/pos/**`, `client/src/pages/retail/**`, `app/PosShell.tsx`, `app/usePosNavigationItems.ts`, `routes/PosRoutes.tsx`,
`pages/POSItemReplacement.tsx`, `pages/settings/Pos*.tsx`, `pages/settings/POSReceiptSettings.tsx`. Paths below are relative to `client/src/`.
Read-only audit; evidence is `file:line`. Items I could not confirm are marked "unverified".

## Routing map (who renders what)

- `routes/AppRoutes.tsx:38-69` — role `POS` -> `PosRoutes`; otherwise hard-coded `location ===` checks for `/retail/pos`, `/retail/stock-count`,
  `/retail/history`, `/retail/reports`, `/retail`, `/retail/inventory`, `/retail/products/*` (no `<Route>`, no permission gate here), then `ErpRoutes`.

- `routes/PosRoutes.tsx:60-86` — non-retail POS user: `/` and `/pos-containers` -> `POSContainerTracking`; `/pos`, `/pos/edit/:id` -> `POS`;
  `/pos-containers/:id`; `/location-inventory` (+history/vouchers, out of scope); `/pos-daybook`; `/pos-dashboard`; `/pos-customers`; `/pos-import`;
  `/vouchers`; `/pos-chat`; `/pos-settings`; `/pos-price-list`; `/pos-transfer-orders`; `/my-settings`; `/help-training`.
- `routes/ErpRoutes.tsx:167` `/pos` -> `POSPage` (switches `RetailPOS` / `POS` by company type, `pages/pos/POSPage.tsx:8-11`); `:174` `/pos/edit/:id` -> `POS`;

- Settings: `pages/Settings.tsx:43` -> `PosSetupHub`; `settings/ExportCenter.tsx:24` -> `PosWhatsAppSection`; `settings/PreferencesTab.tsx:3` -> `POSReceiptSettings`.

## Inconsistency findings

1. **Seven different page-header implementations in one shell.** `PageHeader` with child actions (`pos/POSImport.tsx:23`, `pos/PosTransferOrders.tsx:94`, `pos/pospricelist/PriceListToolbar.tsx:24`); `PageHeader` wrapped in a flex div with actions as siblings (`pos/POSCustomers.tsx:123-131`, `pos/POSDashboard.tsx:253-254`); custom hero (`pos/POSDaybook.tsx:308-320`, `pos/POSContainerTracking.tsx:329`); custom `POSHeader` (`pos/pos-components/POSHeader.tsx:108`); raw `<header><h1>` (`pos/RetailPOS.tsx:442`); raw `<h2>` (`pos/POSSettings.tsx:76`); raw `<h1>` + icon, sometimes inside a bordered card (`retail/RetailInventory.tsx:364`, `retail/RetailStockCount.tsx:249-253`, `retail/RetailSalesHistory.tsx:121-124`, `retail/RetailDashboard.tsx:304-308`). No file under `pages/retail/` imports `PageHeader`/`PageShell`/`ErpPage`. Standard: `ErpPage`/`PageHeader` with actions as children everywhere; full-height POS workspaces get one shared compact variant. Size M, risk low (POS/Daybook/Containers have bespoke CSS hooks such as `pos-daybook-hero`, so those are M-L).
2. **Page container widths/padding differ per page.** `max-w-[1700px] p-4 md:p-6` (`retail/RetailDashboard.tsx:301`), `max-w-[1600px] p-4 pb-24` (`retail/RetailInventory.tsx:360`), `max-w-[1600px] p-3 pb-24 md:p-5` (`retail/RetailStockCount.tsx:247`, `pos/RetailPOS.tsx:439`), `max-w-[1400px]` (`retail/RetailSalesHistory.tsx:119`), `container mx-auto p-4 md:p-6` (`pos/POSCustomers.tsx:122`), `max-w-6xl` (`pos/POSDashboard.tsx:251`), `max-w-md` (`pos/POSSettings.tsx:74`); plus the shell adds `p-3 sm:p-6` for non-full-height routes (`app/PosShell.tsx:360`), so retail pages get double padding in the POS shell (`/retail/stock-count` is not in `isFullHeightRoute`). Standard: `PageShell` owns width/padding. Size S-M, risk low.
3. **Native `<select>` used throughout retail while the legacy POS uses shadcn `Select`.** Native: `pos/RetailPOS.tsx:468,504,596`; `retail/RetailInventory.tsx:400,411,422`; `retail/RetailVariantReports.tsx:136-167` (5); `retail/RetailFinancialPanel.tsx:148,168,186`; `retail/RetailSupplierImportDialog.tsx:477,498,549`; `retail/RetailDashboard.tsx:347`; `retail/RetailSalesHistory.tsx:283`; `retail/RetailStockCount.tsx:262`; `pos/RetailReturnDialog.tsx:357,370`; `pos/RetailShiftPanel.tsx:288`. shadcn: `pos/POSContainerTracking.tsx:407-462`, `pos/pos-components/PosCheckoutStrip.tsx:80-176`, `pos/PosTransferOrders.tsx:144`. Each native select re-declares its own class string (`h-10 … px-2` vs `h-9 … px-3`). Standard: shadcn `Select` (or one shared `NativeSelect` wrapper if the native picker is wanted on phones). Size M (about 30 occurrences), risk low-medium (test ids, `<RetailPaymentAccountOptions>` renders `<option>`s).
4. **Date filters: `PeriodFilter` vs native date inputs.** `PeriodFilter`: `pos/POSDaybook.tsx:341`, `pos/pospricelist/PriceListToolbar.tsx:175`. Native: `retail/RetailDashboard.tsx:330,339` (raw `<input>`), `retail/RetailSalesHistory.tsx:267,276` and `retail/RetailVariantReports.tsx:176-177` (`Input type=date`), `pos/PosTransferOrders.tsx:133`, `pos/POSContainerTracking.tsx:168`, `pages/POSItemReplacement.tsx:360,372`, `pos/pos-components/PosCheckoutStrip.tsx:134`.
