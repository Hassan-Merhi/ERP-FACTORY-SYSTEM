# 05 — Factory: Sales / Loading / Dispatch / Containers / Invoices / Proformas / Allocation

Scope: ~200 non-test files, ~53k lines under `client/src/pages/factory/` (paths below are relative to that folder unless prefixed).
Method: route map from `components/FactoryRoutes.tsx`, `lazyPages.ts`, `shared/factoryAccessRegistry.ts`, `factory/config/navigationPresentation.ts`; import graph for every top-level file; repo-wide pattern greps over the whole scope; direct reading of headers/toolbars/export code of every routed page. Sub-component folders (dialogs, planner panels) were grep-profiled, not read line by line — cells based only on grep are marked `(g)`.

Scope-wide facts (grep over all scope files):
- `ErpPage`, `PageShell`, `OperationsScreen`, `FinancialScreen`, `ErpListTable`, `ErpReportExportMenu`, `SearchField`, `PeriodFilter`, `DatePickerInput`, `page-state` (`EmptyState/LoadingState/ErrorState`), shared `PaginationBar`, shared `StatCard/KPICard`, `Can/useCan`: **0 uses**.
- `PageHeader`: 14 files. Hand-rolled `<h1>` hero headers: 13 files.
- Tabs: all tab bars use `TabsList` + `PillTabButton` (good); only the 2 hubs use `useHubQueryState`.
- Confirm: `ui/alert-dialog` directly in 16 files, `ConfirmationDialog` 2, `ConfirmDialog` 1, native `window.confirm` 1.
- Raw `<table>`: 25 files; shadcn `Table`: 35 files.
- Native `<input type="date">`: 16 files; native `<select>`: 5 files.
- i18n (`useApplicationLanguage`/translation maps): 7 files only; everything else is hard-coded English.

## Inconsistency findings

1. **Customer invoice export is implemented 5 different ways with 3 label sets.**
   - `factoryinvoices/InvoiceOrderRow.tsx:301-347` icon-only Download dropdown, items "Excel / Excel (No Charges) / PDF / PDF (No Charges)", uses `/export/excel` for the first item and `/export-excel?noCharges=1` for the second (two URL spellings of the same endpoint — both registered server-side in `server/routes/factory/customer-orders/orderExcelExportRoutes.ts:69-70`).
   - `FactoryInvoiceDetail.tsx:317-333` "Actions ▸ Export": "Download Excel / Download Excel (No Charges) / Download PDF / Download PDF (No Charges)".
   - `FactoryInvoiceDetailBilingual.tsx:57-103` a second dropdown on the same page, button "Document Language", items "English PDF / English Excel / English Loading List / فاتورة PDF عربية …".
   - `FactoryPendingInvoiceVerify.tsx` Actions menu, same labels as Detail but different testids.
   - `FactoryPendingInvoices.tsx:281-296` two icon buttons using `window.open(…export-pdf, "_blank")` and a bare `<a download>`.
   - The fetch+blob downloader is copy-pasted 4× (`FactoryInvoices.tsx:107-145`, `factoryinvoicedetail/useFactoryInvoiceDetailModel.tsx:503-535`, `factorypendinginvoiceverify/useFactoryPendingInvoiceVerifyModel.tsx:464-499`, `FactoryInvoiceDetailBilingual.tsx:22-55`) while `@/lib/downloadBlob` exists and is used by exactly one file in scope (`FactoryLoadingDispatchReport.tsx:215`).
   - **Standard:** one `FactoryDocumentExportMenu` (wrapping `ErpReportExportMenu` or a thin sibling) fed by `{orderId, kinds:[invoice, invoiceNoCharges, loadingList, loadingStatus], languages}`; one `downloadServerFile(url, fallbackName)` helper in `@/lib/downloadBlob`; one URL spelling. Size M, risk low-medium (touches 5 pages, no server change).

2. **Server-file downloads use 4 transports, so error handling and auth behaviour differ.**
   - fetch+blob+toast: invoices (above), `FactoryLoadingDispatchPostingPanel.tsx:137-153`, `FactoryLoadingDispatchPoExport.tsx:186-219`.
   - `window.open(url, "_blank")` (blank tab, no error toast): `factoryproformas/ProformaCard.tsx:376,391`, `FactoryPendingLoadings.tsx:262`, `FactoryInvoiceLoadingScan.tsx:679,690`, `factoryinvoiceloadingscan/components/SessionHistoryCard.tsx:42,51,125,136`.
   - `window.location.assign(base+"/report.xlsx")`: `FactoryDispatchOrderDashboard.tsx:184`.
   - bare anchor: `FactoryPendingInvoices.tsx:292-296`.
   - `FactoryInvoices.tsx:105` even carries a comment explaining why `window.open` is wrong ("ensures auth cookies are always sent, and surfaces server errors as a toast").
   - **Standard:** the single helper from #1 everywhere. Size S-M, risk low.

3. **Client-side Excel generation uses 2 libraries.** `@/lib/excelHelper` (FactoryContainers.tsx:187, containerExtraExcel.ts:5, FinalizedSaleReturnImport.tsx:178, factoryproformas/useFactoryProformasModel.ts:14, factorycontainerloadingscan/loadedBales.ts:1) vs direct `xlsx-js-style` (`factorystockallocationv5/useFactoryStockAllocationV5Model.tsx:466`). Plus the only manual CSV export in scope (`factoryotwtrackingtab/hooks/useOtwCsvTools.ts:115-119`). **Standard:** excelHelper only; OTW gets Excel like every other list. Size S (V5 styling needs checking — unverified whether excelHelper covers the cell styling used), risk low.
